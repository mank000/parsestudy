# Режимы сбора

## API витрины SATAuto

С 18.11.2026 по умолчанию собираются все статусы. Для отдельной выборки в наличии используйте `./parse api --available-only`; у неё отдельные курсоры. Ранее сохранённые объявления остаются в базе, снятые с продажи не удаляются. Фоновый режим совмещает проверку первых страниц и полный архив: [расписание и ограничения](catalog-sync.md).

`./parse` собирает Китай, Корею и Японию через `/api/carhub/cars` одновременно, по одной цепочке запросов на страну. Каждая страница содержит до 48 записей. Следующая страница страны запрашивается после сохранения предыдущей. Первый запрос каждой страны получает курсор от сервера. Сборщик сохраняет объявления и следующий курсор в одной транзакции. Повторный запуск продолжает с сохранённой позиции и пропускает страны с исчерпанной выдачей.

```sh
./parse api --pages 3
./parse api --country JP
./parse api --country CN --year 2020
./parse api --country KR --year-min 2020 --year-max 2023
./parse api --workers 6
./parse status
```

`Ctrl+C` останавливает сбор. При ответе 409 с сообщением о смене версии каталога сборщик автоматически начинает затронутый диапазон с первой страницы. Сохранённые объявления обновляются по ID. Ручная команда `./parse api --country JP --restart` запускает выдачу выбранной страны заново, `--restart` без страны запускает новый проход по всем трём выдачам. Окончание выдачи API относится к записям этого источника и параметров запроса. Полный список адресов хранится в sitemap.

Страны задаются кодами `CN` (Китай), `KR` (Корея), `JP` (Япония). `--year` выбирает точный год, `--year-min` и `--year-max` задают границы. Допустимы годы от 1900 до 2100. Каждая комбинация страны и годов имеет отдельный курсор. Позиции доступны в `api_selections` команды `./parse status`. Повтор той же команды продолжает выбранную выдачу.

`--workers 6` разделяет оставшуюся выдачу страны на три диапазона — до 2015 года включительно, 2016–2019 и с 2020 года. При заданных годах диапазоны пересекаются с выбранными границами. Каждый диапазон начинается с текущего курсора страны и далее сохраняет свою позицию в `satauto_api_partition`. После остановки сбор продолжает эти позиции даже при уменьшении `--workers`. Страна отмечается завершённой после окончания всех её диапазонов. Состояние диапазонов доступно в `api_partitions` команды `./parse status`.

API проигнорировал параметр `city` в проверке 17 ноября 2026 года. Запросы с Шанхаем и несуществующим городом вернули одни и те же ID и разные города внутри выдачи. Фильтр города для API-сбора пока недоступен.

## HTML-витрина SATAuto

`./parse list` собирает главную страницу витрины, страницы стран и по восемь страниц марок из опубликованного справочника за запуск. Последняя обработанная марка сохраняется в PostgreSQL вместе с объявлениями. Следующий запуск продолжает со следующей марки. Когда справочник исчерпан, следующий запуск начинает обход заново. `--brand-pages 24` меняет размер порции, `--brand-pages 0` обновляет главную и страницы стран, а `--root-only` загружает только главную.

Сборщик сохраняет JSON, встроенный в HTML выдачи, и ссылки из карточек списка. Если поля опубликованы, сохраняются комплектация, год, пробег, топливо, привод, коробка, двигатель, цвет, наличие, цены и фото. Повторное объявление обновляется по ID, ранее загруженные подробности сохраняются. HTML-страницы с выдачей возвращают первую порцию по каждому фильтру. `list_pages_with_more` показывает, сколько обработанных страниц указали на наличие дополнительных результатов, а `brands_remaining` показывает остаток страниц справочника. Подробный расчёт расходов доступен в отдельных карточках. Индекс sitemap содержит адреса опубликованных карточек.

```sh
make sitemap
make parser-run
make parser-resume BRAND=bmw DETAILS=24
make parser-status
```

Индекс строится из всех XML-файлов, перечисленных в sitemap. PostgreSQL заменяет индекс после полного успешного обхода. Если индекс пуст, сбор начинается со страницы публичного каталога. Отбор марки работает по сохранённому индексу.

В PostgreSQL сохраняются задачи на загрузку карточек. Повторный запуск сначала выбирает готовые задачи прошлого запуска, затем добавляет новые адреса. Карточка с нераспознанным HTML откладывается на 15 минут, остальные адреса порции продолжают обрабатываться. Ответы 404 и 410 помечают карточку недоступной. Завершённые и недоступные карточки пропускаются. Состояние порции и причины отложенных задач доступны через `./parse status`.

Если изменился адрес подробной страницы, сборщик следует перенаправлению на SATAuto при совпадении ID карточки и сохраняет новый путь. Циклические и неподходящие перенаправления откладываются. Число переходов доступно в `redirects_followed`.

Запущенный запрос учитывается как одна попытка в очереди. Сетевой повтор того же HTTP-запроса виден в общей HTTP-метрике сессии. Если процесс прервётся, ожидающие карточки остаются в базе. `make parser-status RUN=4` показывает очередь отдельного прогона.

## Фоновый сбор API SATAuto

Эти команды выполняются в терминале компьютера, в корне проекта. Внутри контейнера для просмотра очереди можно вызвать `python -m catalog queue`.

```sh
./parse all
./parse all --country CN --year 2020
./parse all --country KR --year-min 2020 --year-max 2023
./parse status
./parse logs
./parse stop
```

Команда `./parse all` запускает `catalog.sync` в Docker: до шести независимых цепочек полного архива, а между порциями — до трёх цепочек проверки новых объявлений. `./parse all --workers 3` уменьшает параллельность. Новый вызов с другими фильтрами переключает контейнер на выбранную выдачу. Курсоры и расписание хранятся в PostgreSQL. После временных ошибок — паузы 15, 30, 60, 120, 240 и далее 300 секунд; более поздний `Retry-After` имеет приоритет. Прежний `catalog.worker` доступен для разового полного обхода без расписания.

Сетевые обрывы, тайм-ауты и ответы 408, 429, 500, 502, 503, 504 повторяются. При исчерпании повторов текущая сессия заканчивается, фоновый процесс выдерживает паузу и открывает новое соединение с PostgreSQL для продолжения. Ошибки формата, циклические курсоры и ответы 400, 401, 403, 404, 405, 422 завершают фоновый процесс с диагностикой для проверки. Сигнал остановки передаётся дочернему сборщику, чтобы он завершил текущую работу. Жёсткое завершение оставляет последнюю зафиксированную позицию в PostgreSQL. Состояние доступно через `./parse status`, журнал через `./parse logs`.

Подробный HTML-обход по сохранённому индексу доступен командой `python -m catalog public-html --enrich --all-details --details 96`. Он сохраняет очередь и позицию в индексе.

## CarHub

```sh
make carhub
.venv/bin/python -m catalog crawl --pages 1 --country JP
.venv/bin/python -m catalog crawl --resume 8
```

Для публичной пробы доступно до трёх страниц суммарно, до 100 объявлений на страницу. При сохранении страницы вместе с записями фиксируется курсор. При повторе курсора сбор завершается с диагностикой.

Для согласованного совместимого API используется `CATALOG_API_ORIGIN`. У команды `crawl` параметр `--full` добавляет запрос подробной карточки для каждого ID. Снимок с готовыми карточками можно импортировать из NDJSON или NDJSON в gzip одной транзакцией. [Документация CarHub](https://carhubauto.ru/api/) · [Условия массовой выгрузки](https://carhubauto.ru/offer/)

```sh
.venv/bin/python -m catalog import-export /путь/catalog.ndjson.gz
.venv/bin/python -m catalog report --run 8 --output /tmp/carhub.md
```

В NDJSON одна запись об автомобиле на строку. Обязателен положительный целочисленный `id`. Данные источника, объявления, модели, характеристик, расчёта и медиа передаются в объектах `source`, `listing`, `identity`, `specs`, `pricing` и `media`. Повтор ID или ошибка формата отменяют весь импорт.

## HTTP и метрики

Режим API SATAuto запрашивает следующую страницу сразу после сохранения текущей. HTML, sitemap и CarHub v2 используют `robots.txt` и интервал 1,1 с между запросами. HTTP 503 вызывает до двух повторов с ожиданием `Retry-After` до 120 с на повтор. При отсутствии заголовка используется 60 с. Если повторов не хватило или ждать нужно дольше, текущий прогон завершается. Срок ожидания сохраняется для следующих запусков команд сбора объявлений.

API SATAuto отправляет до шести запросов одновременно. Временная ошибка сервера или сети снижает параллельность до одного запроса. После каждых 20 успешно сохранённых страниц параллельность увеличивается на один до выбранного значения. Новая ошибка сбрасывает этот счётчик. Во время ожидания повтора 503 новые страницы остаются в очереди. При выборе одного точного года страны используется одна цепочка.

Метрики содержат число запросов, статусы ответов, объём, время, количество полученных карточек и отдельные счётчики ошибок. Команды `crawl`, `satauto-api`, `sitemap` и `public-html` принимают `--output` для записи JSON на диск. Чтобы сохранить результат Docker-команды на хосте, можно перенаправить stdout, например `./parse api --pages 8 > /tmp/satauto.json`.
