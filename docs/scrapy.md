# Режимы сбора

## SATAuto

```sh
make sitemap
make parser-run
make parser-resume BRAND=bmw DETAILS=24
make parser-status
```

Индекс строится из всех XML-файлов, перечисленных в sitemap. PostgreSQL заменяет индекс после полного успешного обхода. Если индекс пуст, сбор начинается со страницы публичного каталога. Отбор марки работает по сохранённому индексу.

В PostgreSQL сохраняются задачи на загрузку карточек. Повторный запуск сначала выбирает готовые задачи прошлого запуска, затем добавляет новые адреса. Карточка с нераспознанным HTML откладывается на 15 минут, остальные адреса порции продолжают обрабатываться. Ответы 404 и 410 помечают карточку недоступной. Завершённые и недоступные карточки пропускаются. Состояние порции и причины отложенных задач доступны через `./parse status`.

Запущенный запрос учитывается как одна попытка в очереди. Сетевой повтор того же HTTP-запроса виден в общей HTTP-метрике сессии. Если процесс прервётся, ожидающие карточки остаются в базе. `make parser-status RUN=4` показывает очередь отдельного прогона.

## CarHub

```sh
make carhub
.venv/bin/python -m catalog crawl --pages 1 --country JP
.venv/bin/python -m catalog crawl --resume 8
```

Для публичной пробы доступно до трёх страниц суммарно, до 100 объявлений на страницу. При сохранении страницы вместе с записями фиксируется курсор. При повторе курсора сбор завершается с диагностикой.

Для согласованного совместимого API используется `CATALOG_API_ORIGIN`. У команды `crawl` параметр `--full` добавляет запрос подробной карточки для каждого ID. Снимок с готовыми карточками можно импортировать из NDJSON или NDJSON в gzip одной транзакцией. [Документация CarHub](https://carhubauto.ru/api/) · [Условия массовой выгрузки](https://carhubauto.ru/offer/)

```sh
.venv/bin/python -m catalog import-export /путь/catalog.ndjson.gz
.venv/bin/python -m catalog report --run 8 --output /tmp/carhub.md
```

В NDJSON одна запись об автомобиле на строку. Обязателен положительный целочисленный `id`. Данные источника, объявления, модели, характеристик, расчёта и медиа передаются в объектах `source`, `listing`, `identity`, `specs`, `pricing` и `media`. Повтор ID или ошибка формата отменяют весь импорт.

## HTTP и метрики

Оба паука соблюдают `robots.txt`. Между стартами запросов к одному источнику выдерживается 1,1 с. HTTP 503 вызывает до двух повторов с ожиданием `Retry-After` до 120 с на повтор. При отсутствии заголовка используется 60 с. Если повторов не хватило или ждать нужно дольше, текущий прогон завершается. Срок ожидания сохраняется для следующих запусков команд сбора объявлений.

Метрики содержат число запросов, статусы ответов, объём, время, количество полученных карточек и отдельные счётчики ошибок. Для SATAuto дополнительно выводятся `deferred_details` и `missing_details`. Команды `crawl`, `sitemap` и `public-html` принимают `--output` для записи JSON на диск. Чтобы сохранить результат Docker-команды на хосте, можно перенаправить stdout, например `./parse --details 8 > /tmp/satauto.json`.
