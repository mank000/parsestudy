# Новые объявления, архив и обогащение

По решению 18.11.2026 сохраняются **все** объявления. Снятие с продажи меняет
статус, но не удаляет строку. Отсутствие в первой странице, ошибка запроса и
незавершённый обход не доказывают снятие объявления.

`./parse all` запускает `catalog.sync` в Docker:

1. Проверяет первые 12 страниц по странам примерно каждые 10 минут.
2. Между проверками продолжает полный архив порциями до 120 страниц.
3. После полного окончания повторяет архив через сутки. Новый проход начинается
   с первых страниц; объявления и обогащённые характеристики сохраняются.

Интервал проверки новых — целевой: длинная порция архива или повторы ошибок
могут его увеличить. Менять параметры можно аргументами `catalog.sync`:
`--recent-pages`, `--recent-interval`, `--archive-pages`, `--archive-interval`.
Фильтры `./parse all --country KR --year-min 2020 --year-max 2023` сохраняются;
планировщик ведёт отдельное расписание для каждой выборки.

Это два режима одного контроллера, а не два конкурирующих полных парсера.
Курсоры `recent` отделены от архивных и не передаются источнику как фильтр.
Позиции и расписание хранятся в PostgreSQL; действуют блокировки от дублей,
повторы, backoff, Retry-After и адаптивная параллельность.
При остановке сохраняются уже подтверждённые страницы; продолжение использует сохранённую позицию.

Ручная проверка без сброса архива:

```sh
./parse stop
./parse api --lane recent --restart --pages 12 --workers 3
./parse all
```

Дешёвое окно `recent` не гарантирует получение **всех** новых/изменённых строк:
сортировка источника учитывает качество, комплектность и наличие, а не только
дату объявления. Поэтому ранняя остановка по известным ID не используется,
а полный обход остаётся обязательным. При большом потоке окно надо расширять
по измеренному количеству новинок, а не считать 12 страниц достаточными навсегда.

`vehicle_observation` хранит first_seen_at/last_seen_at успешных наблюдений
после установки этой миграции. Историческая публикация не подменяется временем
миграции. Наблюдение обновляется даже если JSON не изменился.
Свежие список/цена/статус/медиа обновляют соответствующие части сохранённой
карточки; старые подробные характеристики сохраняются и не маскируют новый статус.

## Гипотеза обогащения

Проверка трёх реальных карточек с отсутствующими характеристиками дала ноль
дополнительных полей из проверенных fuel/engine/power/color/transmission/drive.
Это небольшая проба, а не доказательство бесполезности всех карточек.
Для продукта полезнее сначала поддерживать свежий список и статусы,
а обогащение делать отдельной ограниченной очередью по конкретному полю,
доказав на выборке, что карточка действительно его добавляет.
Автоматический массовый обход карточек здесь не включён.

## Скорость и сторонний сервер

Курсор источника — непрозрачная позиция его индекса. Следующая страница одной
цепочки зависит от предыдущей; самодельный курсор не создаёт новый снимок.
При 409 «Catalog version changed» сбрасывается затронутый курсор. Если цепочка
потеряла от 120 сохранённых курсоров, сборщик с 4–6 рабочими слотами может
разбить её на более короткие диапазоны по годам. Границы выбираются по числу
машин каждого года в PostgreSQL. Короткие цепочки успевают закончиться раньше,
и следующий сброс затрагивает меньше работы. Один популярный год может
по-прежнему потребовать много страниц. Раскладка диапазонов сохраняется
при следующем полном обходе.

После двух повторов 502/504 без Retry-After проблемный архивный диапазон
откладывается на 30 секунд. Остальные используют свободные слоты. Если ошибки
почти одновременно возникли у трёх диапазонов, параллельность снижается до
одного запроса и восстанавливается постепенно. 429, 503 и Retry-After
задерживают новые запросы ко всему источнику.

Если несколько архивных диапазонов одновременно получают 502/504 и
ответов 200 нет, исчерпание повторов запускает общую паузу на 30 секунд.
Следующая порция начинает с одного запроса и повышает параллельность после
успешных страниц. В журнале `http_502` и `http_504` сохраняют признаки
первого ответа шлюза за порцию, включая сервер, время ответа и наличие курсора.

В статистике запуска `invalidated_checkpoints` считает курсоры, утраченные
при смене версии индекса, `created_partitions` показывает, на сколько выросло
число диапазонов, а `deferred_scans` считает отложенные диапазоны.

Идентичные процессы дублируют страницы. Ускоряют независимые непересекающиеся
страны/диапазоны, а не одинаковые парсеры.
Разбиение по годам требует проверки записей без года: такие записи могут
не попасть в диапазоны. В текущей базе CN/KR без года не обнаружены; у JP
24 таких записи уже сохранены HTML-сборщиком. Это не доказывает отсутствие
других записей без года у источника. Нельзя объявлять полный охват по числу страниц.

Сторонний сервер может улучшить сеть и обеспечить непрерывную работу, но
без измерений из выбранного дата-центра его выигрыш неизвестен.
У текущего API не требуются cookie/вход; HTTP-подключения Scrapy переиспользует.
Больше сессий не отменяет лимит ответа в 48 записей и ошибки источника.
Разворачивать несколько серверов с одинаковыми курсорами не нужно.
Для последующего распределения необходимы общая очередь, lease задачи,
единый лимит запросов и непересекающиеся диапазоны.
