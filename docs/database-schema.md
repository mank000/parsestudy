# Схема PostgreSQL

| Таблица | Ключ | Назначение |
| --- | --- | --- |
| `crawl_run` | `id` | Источник, режим, курсор, статус, метрики и время доступности следующей попытки |
| `vehicle` | `run_id, car_id` | Поля объявления для фильтров, исходные JSON списка и карточки |
| `vehicle_inventory` | `run_id, car_id` | Подготовленные поля каталога и цен для фильтров и аналитики, обновляемые триггером при записи объявления |
| `vehicle_observation` | `run_id, car_id` | Время первого и последнего сохранённого наблюдения объявления в прогоне |
| `crawl_cursor` | `run_id, kind, country, filter_digest, partition, value` | Курсоры и хеши уже обработанных страниц. SATAuto хранит область поиска в отдельных колонках |
| `sitemap_car` | `car_id` | Путь, страна, марка и модель из опубликованной карты сайта |
| `satauto_detail_task` | `run_id, car_id` | Путь, состояние, число попыток, последняя ошибка и срок повтора |
| `satauto_scan` | `run_id` | Позиция и признак окончания обхода сохранённого индекса |
| `satauto_api_scan` | `run_id, country, filter_key` | Следующий курсор API, число страниц и признак окончания выдачи по стране и диапазону лет |
| `satauto_api_partition` | `run_id, country, filter_key, partition` | Независимые курсоры параллельных диапазонов, созданные из общей позиции страны |
| `satauto_lot_id` | `source_id` | Стабильный локальный ID для японских лотов с буквенно-цифровым ID |
| `trim_reference` | `source, reference_id` | Ключ комплектации, технические поля и происхождение значений |
| `catalog_schema_migration` | `version` | Журнал применённых SQL-миграций |
| `catalog_sync_progress` | `profile, country, filter_key, partition` | Время последнего сохранения страницы для наблюдаемой выборки |

`crawl_run` связан с `vehicle`, `crawl_cursor` и `satauto_detail_task` по `run_id`. Задача может появиться раньше строки объявления. Строки карты сайта связываются с данными SATAuto через ID автомобиля. Совпадения ID между SATAuto и CarHub сохраняются в своих прогонах.

`vehicle.summary` хранит данные списка, `vehicle.detail` — данные подробной карточки. Рублёвая цена продавца хранится в `listing_rub`. Для полного, предварительного и частичного расчётов используются `total_rub`, `estimated_rub` и `known_rub`. Состояние расчёта также приходит в JSON источника.

Представление `vehicle_inventory_source` применяет правила отображения к исходным данным. Триггер `vehicle_inventory_refresh` сохраняет результат в `vehicle_inventory` при добавлении и изменении объявления. При удалении объявления связанные подготовленные поля удаляются каскадно. Инициализация заполняет отсутствующие строки для ранее собранных данных.

При сохранении распарсенного объявления обновляется `vehicle_observation.last_seen_at`, даже если его данные совпадают с предыдущими. Для исторических записей без метки время остаётся неизвестным. Индексы по прогону и времени наблюдения, стране, марке с моделью и году дополняют первичный ключ `(run_id, car_id)`.

Задачи SATAuto переходят из `pending` в `complete`, `missing` или `deferred`. Для `deferred` указан `retry_at`. Сохранение подробной карточки и отметка `complete` выполняются в одной транзакции. Для ошибок источника задача может остаться в `pending` до возобновления запуска.

Команда `python -m catalog init` выполняет [пронумерованные SQL-миграции](../catalog/migrations) под транзакционной блокировкой PostgreSQL. Уже применённые версии берутся из журнала. В существующей базе начальная миграция проверяет прежнюю схему, а вторая переносит ключи курсоров SATAuto в отдельные колонки. Перед обновлением остановите сборщик и сделайте копию базы. После миграции запустите компоненты на одной версии приложения.
